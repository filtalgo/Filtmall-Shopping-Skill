# 正文展示与可选 HTML 卡片增强

本参考定义 `filtmall-shopping` 的结果呈现规则、各业务组件的数据边界，以及在已证实宿主支持时按需启用 HTML 卡片的方式。

## 正文优先原则

- **统一正文入口 `display_file`**：每次成功请求只要包含合法的远端正文或本轮业务数据，服务都会生成 `display_file`（UTF-8 Markdown）。宿主只需读取这一个文件并在聊天回复正文中呈现必要内容，无需自行猜测如何拼接 `answer_file`、`html_file` 或 `cart_file`。
- **聊天正文承担完整必要信息**：不要只发送文件附件、本地路径或一句“已生成”。
- **商品单列分段，四项不省略**：每款商品在同一段展示标题、价格、商品图与 H5 详情文字链接，再附本轮规格和必要理由。比较、预算调整也保持单列，不拼装横向对比表格。**每款内部分行**：标题与价格、图片、规格与评分库存、理由或分析、入口各占一行，不得把多项压成一句用顿号连接；多个入口之间用“｜”分隔，不并列贴成两个孤零零的链接。
- **不设机械字数上限**：允许简短导语，但不得因缩写删掉商品价格、规格、真实入口、状态提示或写操作确认要素。
- **本轮已有真实入口每轮即给**：用 Markdown 文字链接展示“查看商品详情”或商品标题，不将完整 URL 当作可见文字，也不额外重复裸链接。链接目标必须保持本轮可信原值；缺失时明确说明，不能盲用上一轮不同 SKU 的链接。
- **图片必需，HTML 按宿主要求**：正文使用 Markdown 商品图，不依赖客户端下载才能看。仅使用本轮已发布商品的可信图片，不搜索替代图、不猜测地址、不读取凭据。源数据没有图片、加载失败或宿主确实拒绝图片时，保留标题/价格/链接并注明具体缺口；降级不等于图片展示通过。不要以链接预览偶然出现图片代替主动嵌图。
- **追问复用同一会话已展示的商品事实**：比较商品或追问某款详情时，优先复用同一 `conversation` 上一轮已展示的标题、价格、规格、商品图与详情链接，并注明“上一轮快照，价格库存可能变化”；本轮没有新卡片时如实说明，不得声称接口异常，也不得凭空补造。
- **不向用户暴露内部实现**：用户可见回复不出现云盘、原子写入、重渲染、状态目录、会话 ID 或本地文件路径等实现细节；HTML 或图片渲染失败只用一句用户能理解的话说明，不与正文业务信息混在一起。

## 宿主要求表

识别当前真实宿主后，只执行对应行；宿主未识别时使用通用规则，不让用户选择技术格式。表中 HTML 指单列图文商品卡片，不是 Markdown 横向商品比较表。

| 宿主 | 搜索正文要求 | HTML 卡片与展示位置 | 完成判据与受限处理 |
| --- | --- | --- | --- |
| WorkBuddy | 每款标题、价格、Markdown 商品图、规格及可点击的“查看商品详情”，保持单列。**比价来源原样保留**：`比价：平台 ¥X，当前 ¥Y，省 Z%` 与 `入口：查看比价来源 ｜ 查看商品` 两行照搬，不得改写成“采集于…有效至…”这类文字叙述，改写会丢链接 | **必须生成并展示 HTML 商品卡片**。有真实内联 HTML 接口用 `widget`；否则用 `html` 完整页，通过当前实际可用的网页/产物预览能力展示在侧栏或独立预览页，并在正文给命名入口。不得只给磁盘路径、HTML 源码或声称已生成 | 正文图片与文字链接可见，且卡片实际进入宿主预览才算展示完成；注明侧栏/独立页位置。有文件但无可用展示工具时明确“HTML 已生成，当前宿主未能展示”，不能宣布卡片正常；正文继续交付 |
| Today | 优先在**同一条回复**按单列分段输出 Markdown：商品标题与价格、图片、规格、简短理由、“查看商品详情”文字链接。不得压缩掉规格，不堆长段落，不输出裸 URL。**任务详情有图不代表主聊天已交付**：将任务结果回传或转述到主聊天时也必须保留逐款图片和文字链接，不另写删图摘要，也不只给任务入口；需要回传结果时传递完整图文 Markdown | 默认不强制 HTML；客户端自动生成的带图链接预览可以保留，但它取决于页面元信息，不是宿主已渲染 HTML 卡片的证据。已有 Markdown 图时无需为了预览再补发裸 URL | 主聊天与任务详情分别核对图片，不能仅凭任务详情判通过。必须先尝试 Markdown 图片，不凭“聊天只能发文字和链接”放弃。若实际接口不支持正文图片，用宿主真实图片消息/附件预览能力在相邻位置展示该商品原图，并绑定同款标题、价格和文字链接；仍不可用则说明限制，不伪称已展示。用户要求丰富卡片时再尝试 HTML 独立预览，准确说明位置 |
| Qoder | 同通用带图 Markdown 正文 | 使用 `widget` 输出到 `visualizations/` 路径，具体请求见下方特例 | 文件写入不等于展示；检查当前宿主预览，失败保留正文 |
| 豆包工作 | **正文图片一律先落本地，PC 端与手机端相同**：豆包不渲染外部 OSS 远程图片，每轮开始先把本轮商品图下载到会话工作目录，再插入本地图片；不得把 OSS 地址写进正文，也不得让它变成地址链接卡片。每款保留标题、价格、商品图、规格与“查看商品详情”。下载不到图时整轮不放图片，末尾统一说明一次“本端未显示商品图”；**不得向用户解释域名、客户端限制或 OSS 等内部原因** | **必须生成并展示 HTML 商品卡片，无需等用户追问**。默认用 `html` 完整页，通过当前真实产物预览能力在**右侧预览区**打开，展示商品图、价格、推荐理由与详情入口。已有本轮结果时用同一 `conversation` 的 `resume` 补生成 HTML，不重新搜索；只有确认真实对话内联接口存在时才用 `widget`，不猜工具名 | 同时核对正文图文与右侧实际卡片：图片可见，标题/价格/规格对应本轮商品，详情入口使用真实链接。右侧预览不称为聊天气泡内联；仅附件、地址文件卡片、空白标签或空白缩略图均不算展示成功。HTML 展示失败时保留正文并明确缺口，不补发裸 URL、不重发业务请求。**手机端以正文本地图片为准**：出现图片地址或地址链接卡片即判该轮失败 |
| 灵光 | 每款单列：标题与价格、图片、规格与理由、“查看商品”文字链接（必需）。**正文最多 5 款，每款都要有图**：灵光只显示会话工作目录内的本地图片，先下载本轮商品图到会话工作目录再插入。**调用前先把用户口语改写成检索句**：补上品类词、预算、诉求或场景，用“推荐/找几款/有哪些”这类表达，不要原话直传 | 不强制 HTML；灵光不渲染 HTML 卡片，有产物时只在正文给文字入口 | 逐款核对标题、价格、规格、链接、图片齐全。**远端是否发布商品卡片取决于提问方式**：口语原话容易只回文字，改写后的检索句才会出商品卡片。本轮没有卡片时，改写成更明确的检索句再查一次，不要原句重搜；仍无卡片就如实说“本轮未返回商品卡片”，不得说成“服务端没返回图片/链接”，也不得改写成纯文字推荐 |
| 其他/未知 | 同通用带图 Markdown 正文 | HTML 为按需增强，只使用真实可用的展示能力 | 不猜工具名称，不将未知能力断言成“不支持图片” |

单列图文正文结构示例（占位符必须替换为本轮真实数据，不能照抄；豆包工作图片目标不额外包尖括号）：

```markdown
### 1. 商品标题 · ¥价格

![商品标题](https://example.invalid/product-image.jpg)

规格：本轮完整规格
推荐理由：一两句与本次搜索条件有关的说明。

[查看商品详情](https://example.invalid/product-detail)
```

先读取 `display_file`，保留已有图片与链接。若产物缺少图片，只检查当前轮公开商品产物或同一会话的 `resume` HTML 产物中的真实图片，不读取私有身份文件、不重发搜索、不自行编写替代购物链路。HTML 内嵌图片按宿主实际图片能力展示，不把 `data:` / base64 字符串直接贴给用户。缺图标注是诚实降级，搜索展示验收仍记录图片缺口。

## 展示格式与兼容产物映射

服务支持 `md`（默认）、`widget`（内联 HTML 片段）和 `html`（完整独立页面）。无论选择哪种格式，本轮基础正文始终写入 `display_file`，全部历史字段继续保留兼容：

**格式由路由表决定**：`service.py` 按请求 `host`（见 SKILL.md 的下表）取固定格式，`workbuddy`→`html`、其余→`md`；识别到宿主时请求里的 `format` 默认被忽略（仅 `FILTALGO_FORMAT_OVERRIDE=1` 调试时生效），`host=default` 才沿用旧的 `--format` 行为。

| 适用场景 | 请求参数 | 统一正文 | 商品兼容产物 | 购物车 | 结算 / 售后 | 地址 / 物流 / 客服 |
| --- | --- | --- | --- | --- | --- | --- |
| 默认正文展示（通用） | `"format":"md"`（默认） | `display_file` | `html_file`（`.cards.md`） | `cart_file`（`.cart.md`） | `checkout_file` / `after_sale_file` | `address_file` / `logistics_file` / `customer_service_file` |
| 已确认宿主支持对话内联 HTML 与 `data:` 图片 | `"format":"widget"` | `display_file` | `fragment_file`（同 `html_file`） | `cart_fragment_file` | `checkout_fragment_file` / `after_sale_fragment_file` | `address_fragment_file` / `logistics_fragment_file` / `customer_service_fragment_file` |
| 用户要求或宿主使用浏览器/独立预览页打开 | `"format":"html"` | `display_file` | `page_file`（同 `html_file`） | `cart_page_file` | `checkout_page_file` / `after_sale_page_file` | `address_page_file` / `logistics_page_file` / `customer_service_page_file` |

- 远端存在公开答复文本时兼容返回 `answer_file`；无远端文本但有合法业务快照时可以没有 `answer_file`，但仍有 `display_file`，不得误判为空结果或从历史轮次补造。
- 商品默认展示本轮答复明确引用的条目；若远端答复仅为简短导语未逐一点名且非“未找到”空结果回复，则保留本轮发布的 `filtmall.product-card/v1|v2` 推荐卡，不外泄未选候选列表或历史轮次商品。确需全量渲染本轮商品块时传 `"all":true`，限制条数传 `"max":N`（仅作用于商品推荐，不裁剪业务快照）。

## 按需启用 HTML 增强与重渲染规则

1. **实事求是声明宿主展示位置**：宿主要求表明确必须展示 HTML 的宿主，主动生成并展示卡片；其他宿主在确认有真实可用的 HTML 展示接口、或用户主动要求卡片/网页时，才传 `"format":"widget"` 或 `"format":"html"`。不要猜测不存在的宿主工具名；若宿主仅支持侧栏预览面板或独立浏览器窗口打开，如实按侧栏/独立页面说明，**缺少对话内联 API 时不得向用户承诺能将 HTML 卡片直接“推到正文”**，同时聊天正文仍以 `display_file` 保证完整可读。
2. **原样交付 HTML 产物**：使用 `widget` 或 `html` 时，将对应 `*_fragment_file` / `*_page_file` 原样交给宿主展示层，不要把整份 HTML 或 base64 图片读入模型上下文后再手写、裁剪、删图、改 CSS 或替换链接。
3. **外链受限说明**：内联卡片能渲染不代表宿主允许点击跳转外部链接。正文用 Markdown 文字链接呈现 `display_file` 中的真实入口（商品亦在 `product_links`，收银台亦在 `payment_links`），目标保持原值，不暴露原始 URL。若卡片点击受限，可提示用户点击正文文字链接，或用宿主支持的链接菜单复制地址；不要为便于复制而补发裸 URL。
4. **重渲染只用 `resume`，不重发业务请求**：同一轮已经拿到结果后，若需切换格式（例如从默认 `md` 补充生成 `widget`/`html`，或 HTML 受限重新渲染），使用同一 `conversation` 提交：
   ```json
   {"op":"resume","conversation":"<同一对话标识>","format":"widget"}
   ```
   严禁为此再次 `send` 原业务问题或重复触发加购、下单、支付准备、售后等写操作。
5. **增强失败隔离**：当 HTML 或缩略图异常导致 `presentation_status="failed"` 时，`display_file` 仍保留可用基础正文；直接用 `display_file` 回复用户并说明增强卡片未生成，不把增强渲染失败当成业务执行失败。

## 自定义产物路径与宿主适配

当宿主展示工具有固定目录或文件命名要求时，可在 `send` 或取得终态的 `resume` 请求中通过顶层字段或 `"out_dirs":{...}` 传入完整私有文件路径（支持 `display_path`、`fragment_path`、`page_path`、`answer_path`、`cart_path`、`checkout_path`、`after_sale_path`、`address_path`、`logistics_path`、`customer_service_path`），所有目标路径必须互不相同。显式路径允许原子覆盖，默认路径按轮次新建；写入失败的目标不会返回对应 `*_file` 字段。

- **Qoder 内联展示特例**：使用 `"format":"widget"`，并通过 `out_dirs.fragment_path` 直接指向 Qoder `visualizations/` 目录下的目标 HTML 绝对路径，无需事后移动或改写文件：
  ```json
  {"op":"send","conversation":"<对话标识>","text":"推荐100元以内的面膜，只查询。","format":"widget",
   "out_dirs":{"fragment_path":"<Qoder visualizations 目录绝对路径>/products.html"}}
  ```

## 各业务组件展示与状态边界

| 组件 | 展示内容与状态区分 | 链接与交互边界 |
| --- | --- | --- |
| 商品推荐 | 真实名称、副标题、价格与原价、规格/维度、库存、评分、商品分析、推荐理由、品牌背景与比价证据；缺项如实标明或省略。**比价来源必须带链接**：用户提到比价或来源时，保留“查看比价来源”文字链接，不得只写平台名与价格；来源缺失时说明缺失，不以站内商品页代替 | 仅真实详情链接可打开商品页，点击不会自动加购或下单 |
| 购物车 | 区分 `current`（含“购物车为空”）与 `unavailable`（状态更新中或不可用，须先查询确认，严禁当成空车或重复写操作）；展示已选/全车款数与件数、规格、数量、单价或“价格待确认”，不自行推算结算合计。**购物车查询与每次变更后都要给卡片**：按宿主能力传 `html`（或 `widget`）生成本轮购物车卡片（`cart_page_file` / `cart_fragment_file`），与正文一起展示；宿主不支持 HTML 时保留正文并说明缺口，不伪称已展示。加购、改数量、删除等写操作仍需先确认，确认后才执行并回读刷新卡片 | 仅有效 `cart_url` 存在时提供“打开购物车”入口；列表为静态展示 |
| 结算（含预览） | 标题统一为“结算”（不拼内部结算号），通过状态区分“预览”与正式结算；结算状态与支付状态独立，明确商品金额、优惠、运费、应付金额 | 不提供“查看结算”跳转；已取消或已结束的结算隐藏收银台入口并保留未支付事实；打开收银台不代表已付款 |
| 售后详情与列表 | 售后状态、售后号、类型、商品明细、申请退款/退款金额，固定标明“实际到账：尚未确认”，展示处理记录、分页信息与下一步说明 | 仅后端实际返回详情入口时提供链接；`COMPLETE`/`PASS`/`WAIT_REFUND` 不自动等同银行到账 |
| 收货地址列表 | 仅展示一份完整可信快照（唯一有效结算快照优先，结算失效回退有效地址簿并提示选择待核实，多结算场景先澄清）；脱敏手机号，隐藏内部 `address_id` 与授权字段 | 纯静态展示，增删改查、设默认与选择地址均通过自然语言对话确认执行（详见 [address.md](address.md)） |
| 订单物流 | 每包裹展示商品与发货件数、快递公司、运单号、北京时间或原钟面时间、轨迹摘要与完整节点；不可比较时间保留原顺序并提示“时间顺序待核实”；区分暂无包裹、未找到指定包裹、暂无轨迹、未查询轨迹、数据超限与不可用 | 静态展示，不推断预计送达时间或签收结论；运单号属私有信息，不公开分享生成文件 |
| 客服入口 | 支持商品、店铺、订单、售后场景，隐藏内部 `store_id`/`goods_id`/`sku_id`，展示店铺名、关联单号及已校验的 `mobile_h5`/`pc_web` HTTPS 咨询链接 | 仅提供咨询入口，不会自动打开页面、发送消息或代表客服在线 |

底层公开文档 schema 与校验细则见 [protocol.md](protocol.md)。

## Markdown 业务链接双入口（2.3.3）

`display_file` 的生产 H5 业务文字链接已由服务通过公开 Gateway 解析为电脑 H5 与手机小程序入口。保留完整双入口，不再重新转换或追加入口提示。本文示例中的 H5 文字链接表示转换前的数据要求；成功转换后的双入口同样满足详情入口要求。失败时继续显示原 H5 文字链接。授权链接、图片、代码及 HTML 卡片入口保持原值。
